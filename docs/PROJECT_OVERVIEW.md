# PROJECT_OVERVIEW

## Что это

Универсальный агент-парсер на Claude Code и Firecrawl MCP с архитектурным разделением детерминированного workflow и агентских узлов, и доменно-нейтральным слоем безопасности, который соответствует современным правилам разработки агентных систем (Anthropic «Building Effective Agents», OWASP Top 10 for LLM Applications 2025, NIST AI 100-2).

## Цели

Извлечение структурированных данных с произвольных веб-источников (новости, документация, e-commerce, объявления, справочные базы) с гарантиями: воспроизводимость, аудируемость, контроль стоимости, защита от prompt injection через скрапленный контент, валидация по схеме до записи в БД.

Доменная специфика добавляется как адаптер в `src/sources/<domain>.py` — ядро остаётся неизменным.

## Не-цели

Проект **не делает** ни одно из следующего, и это намеренно:

Не строит универсального «AI-исследователя», который сам решает, что и где парсить. Решение о новом источнике принимает человек (HITL-gate), агент только помогает с разовым онбордингом адаптера.

Не работает с источниками, требующими аутентификации/обхода капчи/нарушения ToS. Если у площадки есть публичный API — используем его, scrape не альтернатива API.

Не хранит персональных данных без явного запроса и juridical basis. Поля типа `email`, `phone`, `address` фильтруются на extraction-слое по умолчанию.

Не использует «hosted MCP с ключом в URL», `acceptEdits` mode по умолчанию, `firecrawl_crawl` без `limit` — эти антипаттерны явно запрещены в `.claude/settings.json`.

Не использует live-вызовы Firecrawl в CI: per-PR eval работает на frozen fixtures, без сетевых вызовов и API-ключей.

## Целевые пользователи

Команды от 1 до ~5 разработчиков, которым нужен контролируемый, аудируемый scrape-pipeline с поддержкой нескольких источников и периодической регрессией. Не подходит для one-off ad-hoc парсинга (для этого достаточно прямого вызова Firecrawl).

## Ключевые принципы

**Workflow first.** Агент включается только там, где задача принципиально неструктурирована: онбординг нового источника, расследование валидационных аномалий, трансляция запроса пользователя в SQL-фильтр.

**Untrusted by default.** Любой контент, вернувшийся через Firecrawl, проходит sanitize-слой и injection classifier до того, как попадает в контекст LLM или в БД.

**Eval-driven.** 20 эталонных fixtures (смешанный тип) проверяются на каждый PR через GitHub Actions. Без зелёного eval merge заблокирован.

**Append-only audit.** `raw_content` неизменяема и хранит все попытки скрапа с `content_hash` и `trace_id` — это позволяет перепроиграть extraction без повторных запросов к Firecrawl.

**Cost-bounded.** Каждый Firecrawl-вызов обёрнут в `CostGate` с `max_credits_per_run`, `max_iterations`, circuit breaker'ом. Runaway loop невозможен по конструкции.
