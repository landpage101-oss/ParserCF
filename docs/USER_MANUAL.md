## 1. Что делает эта программа

**Agent-parser** — это автоматический парсер веб-страниц. Он заходит на указанные сайты,
извлекает структурированные данные (заголовки, тексты, даты, авторов и т.д.) и сохраняет
их в локальную базу данных SQLite.

Программа устроена так, что человек всегда контролирует процесс:

- Список сайтов для парсинга — задаётся явно в конфиге, случайных запросов нет.
- Стоимость каждого запуска ограничена — нельзя случайно «сжечь» тысячи кредитов Firecrawl.
- Весь контент с сайтов сначала проходит проверку безопасности — защита от атак через
  скрапленные данные.
- Каждый успешный результат проходит валидацию по схеме — мусор не попадает в базу.

Сейчас в системе три источника: документация Python (`docs.python.org`),
MDN Web Docs (`developer.mozilla.org`) и новости Anthropic (`www.anthropic.com`).

- `scripts/check_db_state.py` — проверить, что в базе.
- `scripts/resolve_vf.py` — разобрать ошибки валидации.
- `src/run.py` — главная программа (запускается через `python -m src.run`).

## 3. Установка и первый запуск

### 3.1 Требования

- Python 3.12 или новее.
- API-ключи: `FIRECRAWL_API_KEY` и `ANTHROPIC_API_KEY`.

### 3.2 Установка зависимостей

Откройте терминал в папке проекта и выполните:

```powershell
# Создать виртуальное окружение (один раз)
python -m venv .venv

# Активировать его (Windows PowerShell)
.\.venv\Scripts\Activate.ps1

# Установить зависимости
pip install -e ".[dev]"
```

После установки в папке `.venv/Scripts/` появятся все нужные утилиты: `pytest`, `ruff`,
`mypy` и другие.

### 3.3 Настройка API-ключей

Скопируйте шаблон и заполните ключи:

```powershell
copy .env.example .env
```

Откройте файл `.env` в любом текстовом редакторе и вставьте ваши ключи:

```
FIRECRAWL_API_KEY=fc-ваш_ключ_здесь
ANTHROPIC_API_KEY=sk-ant-ваш_ключ_здесь
```

> **Важно:** файл `.env` добавлен в `.gitignore` и никогда не попадёт в git. Никогда не
> вставляйте ключи напрямую в код.

### 3.4 Инициализация базы данных

При первом запуске база создаётся автоматически. Если нужно создать её вручную:

```powershell
python -c "from src.db.migrate import run_migrations; run_migrations()"
```

## 4. Основные команды: запуск батча

«Батч» — это один прогон парсера по всем URL заданного источника.

### 4.1 Базовый запуск

Запустить батч для конкретного источника:

```powershell
python -m src.run --source developer_mozilla_org
python -m src.run --source docs_python_org
python -m src.run --source anthropic_news
```

Имена источников — это названия файлов адаптеров без расширения (например, файл
`src/sources/developer_mozilla_org.py` → имя `developer_mozilla_org`).

### 4.2 Что происходит во время батча

Программа для каждого URL из списка адаптера:

1. Проверяет `robots.txt` сайта — разрешён ли парсинг.
2. Проверяет базу данных — не скрапили ли мы этот URL недавно (см. `--max-age-days`).
3. Если всё ок — делает запрос через Firecrawl.
4. Проверяет, не превышен ли бюджет кредитов.
5. Сохраняет «сырой» ответ в таблицу `raw_content` (аудит-лог, никогда не удаляется).
6. Валидирует данные по схеме. Если не прошло — запись идёт в `validation_failed`.
7. Если прошло — сохраняет в `canonical_records` (финальная база).

В конце батча выводится итоговая строка, например:

```
batch done: {'canonical': 19, 'validation_failed': 0, 'skipped_robots': 0,
             'errors': 0, 'skipped_fresh': 0}, credits_used=95, root_span_id=abc123
```

### 4.3 Параметры командной строки

| Параметр | По умолчанию | Что делает |
|---|---|---|
| `--source` | обязательный | Имя источника (например `docs_python_org`) |
| `--max-credits` | `100` | Максимум кредитов Firecrawl за один батч |
| `--max-age-days` | `7` | Пропустить URL, если в базе есть запись моложе N дней |
| `--force` | выключено | Скрапить все URL заново, игнорируя возраст записей |
| `--max-iterations` | `200` | Лимит на число URL за один запуск |
| `--since` | нет | Фильтр по дате (передаётся адаптеру, не все адаптеры поддерживают) |

Примеры:

```powershell
# Принудительно перескрапить всё, дать больше кредитов
python -m src.run --source developer_mozilla_org --force --max-credits 200

# Использовать свежий кеш (не скрапить то, что обновляли за последние 3 дня)
python -m src.run --source docs_python_org --max-age-days 3
```

### 4.4 Инкрементальный режим (по умолчанию)

Начиная с Phase 5, программа автоматически пропускает URL, у которых в `canonical_records`
есть актуальная запись (моложе `--max-age-days` дней). Это называется «skip-if-fresh».

В итоговой строке такие URL отображаются как `skipped_fresh`. Это нормально и экономит
кредиты: программа сама «догоняет» то, что не успела в прошлый раз.

## 5. Проверка состояния базы данных

Скрипт `scripts/check_db_state.py` показывает, сколько записей в базе по каждому
источнику и есть ли нерешённые ошибки валидации.

```powershell
# Посмотреть общую статистику по источнику
python scripts/check_db_state.py --source developer_mozilla_org

# Посмотреть список всех source_id (идентификаторов страниц)
python scripts/check_db_state.py --source developer_mozilla_org --show-ids
```

Пример вывода:

```
source:        developer_mozilla_org
canonical:     34
unresolved vf: 0
```

Значения полей:

- `canonical` — число страниц, успешно записанных в базу.
- `unresolved vf` — число записей в очереди ошибок валидации, которые ещё не разобраны.
  В норме это 0.

## 6. Работа с очередью ошибок валидации

Если при скрапинге страница не прошла проверку по схеме, запись попадает в таблицу
`validation_failed`. Это очередь проблем, которые нужно разобрать.

### 6.1 Посмотреть нерешённые ошибки

```powershell
python scripts/check_db_state.py --source anthropic_news
```

Если `unresolved vf` > 0, в базе есть проблемы.

Для более детального просмотра используйте SQLite напрямую (в режиме только для чтения):

```powershell
sqlite3 data/scraped.db -readonly "SELECT id, url, error, detected_at FROM validation_failed WHERE resolution IS NULL;"
```

### 6.2 Просмотреть конкретную запись

```powershell
# Посмотреть запись с id=5, ничего не менять
python scripts/resolve_vf.py --vf-id 5 --dry-run
```

Вывод покажет: источник, URL, текст ошибки, дату обнаружения.

### 6.3 Закрыть запись об ошибке

После того как вы разобрались с причиной (например, исправили адаптер или решили
игнорировать ошибку), закройте запись:

```powershell
python scripts/resolve_vf.py --vf-id 5 --resolution fixed --reason "Обновил адаптер, поле теперь извлекается"
python scripts/resolve_vf.py --vf-id 5 --resolution discarded --reason "Страница больше не существует"
python scripts/resolve_vf.py --vf-id 5 --resolution source_changed --reason "Сайт изменил структуру"
```

Допустимые значения для `--resolution`:

- `fixed` — проблема устранена (код или схема исправлены).
- `discarded` — запись признана нерелевантной, страница исключена.
- `source_changed` — источник изменился, это ожидаемо.

## 7. Добавление нового источника

Это многошаговый процесс. Программа не парсит сайты, которых нет в `config/sources.yaml`.

### 7.1 Ручная проверка перед началом

Прежде чем что-то делать, убедитесь в трёх вещах:

1. **Сайта нет в `config/sources.yaml`** — иначе источник уже добавлен.
2. **`robots.txt` разрешает парсинг** — откройте `https://домен/robots.txt` и проверьте
   руками, что парсинг вашим агентом не запрещён.
3. **Есть юридическое основание** — публичные данные, открытая лицензия, нет ToS-запрета
   на автоматическую обработку.

### 7.2 Запустить онбординг через Claude Code

Если у вас настроен Claude Code, используйте slash-команду прямо в редакторе:

```
/onboard-source example.com
```

Claude Code сам разберёт структуру сайта и создаст черновики файлов.

### 7.3 Что создаёт онбординг

После выполнения команды появятся два новых файла:

- `src/sources/example_com.py` — адаптер с методами `list_urls()` и `parse_id()`.
- `tests/sources/test_example_com.py` — тесты адаптера.

И блок YAML для ручного добавления в `config/sources.yaml`.

### 7.4 Что нужно сделать вручную

Онбординг создаёт **черновик** — финальное решение за вами:

1. Проверьте seed-URL в адаптере — верны ли они?
2. Запустите тесты: `pytest tests/sources/test_example_com.py -v`
3. Добавьте YAML-блок в `config/sources.yaml` (это CODEOWNERS-файл, Claude Code сам его
   не редактирует).
4. Сделайте тестовый батч: `python -m src.run --source example_com --max-credits 20`

### 7.5 Структура адаптера

Каждый адаптер — это Python-класс с тремя атрибутами и двумя методами:

```python
class ExampleComAdapter:
    page_type = "article"      # тип страниц: article | docs | product | reference
    domain = "example.com"
    name = "example_com"

    def list_urls(self, since=None):
        # Возвращает список URL для скрапинга
        return ["https://example.com/page1", "https://example.com/page2"]

    def parse_id(self, url):
        # Извлекает канонический идентификатор страницы из URL
        return url.removeprefix("https://example.com/")
```

## 8. Агентские роли: три slash-команды

Программа поддерживает три режима работы с Claude Code (агентские роли). Каждая роль
имеет строго ограниченный набор инструментов.

### `/query <запрос на естественном языке>`

Переводит вопрос в SQL-запрос к базе данных и возвращает результат. Только чтение.

```
/query сколько статей в canonical_records
/query все страницы источника docs_python_org
/query страницы с более чем 10 блоками кода
```

Возвращает таблицу до 50 строк. Не делает сетевых запросов, не меняет данные.

### `/investigate-failed <источник>`

Разбирает свежие записи из `validation_failed` по заданному источнику, ставит диагноз
каждой ошибке и предлагает действия. Результат сохраняется как отчёт в
`reports/investigations/`.

```
/investigate-failed anthropic_news
```

Диагнозы, которые ставит агент:

- `structure-drift` — сайт изменил разметку, поле больше не извлекается.
- `anti-bot` — вместо контента пришла страница с капчей или Cloudflare.
- `redirect` — вместо контента пришла страница логина или лендинг.
- `adapter-bug` — ошибка в коде адаптера (неверный URL или ID).
- `schema-too-strict` — валидатор схемы слишком строгий, легитимный контент отвергается.

Роль только читает и пишет отчёты — код и базу не трогает.

### `/onboard-source <домен>`

Создаёт черновик адаптера для нового источника. Подробнее — в разделе 7.

## 9. Как работает защита: safety-слой

Любой контент, полученный с сайта, считается **недоверенным**. Прежде чем он попадёт в
базу или в контекст ИИ, он проходит два уровня проверки.

### 9.1 Sanitize (очистка)

Файл `src/safety/sanitize.py` выполняет следующее:

- Удаляет невидимые Unicode-символы (zero-width space, bidi-overrides и другие) —
  их используют для скрытых инъекций.
- Нейтрализует ролевые префиксы (`system:`, `assistant:`, `user:` в начале строки),
  которые могут сбить с толку языковую модель.
- Удаляет визуально скрытые HTML-элементы (`display:none`, `opacity:0`, `color:white`) —
  классический вектор prompt injection.
- Ищет паттерны инъекций (`ignore previous instructions`, `you are now` и подобные).

Если что-то подозрительное обнаружено, поле помечается предупреждением, но батч
продолжается — это данные, а не инструкции.

### 9.2 Classifier (классификатор)

Файл `src/safety/classifier.py` работает поверх очищенного контента и добавляет
семантическую проверку.

### 9.3 Robots.txt

Перед каждым запросом программа проверяет `robots.txt` сайта. Если парсинг запрещён —
URL пропускается (счётчик `skipped_robots` в итоговой строке).

## 10. Ограничения по стоимости (CostGate)

`CostGate` — встроенный предохранитель, который не даёт программе тратить больше
заданного бюджета за один прогон.

### 10.1 Как это работает

Перед каждым вызовом Firecrawl программа проверяет три условия:

- **Кредитный лимит:** `credits_used + 5 > max_credits_per_run` → стоп.
- **Лимит итераций:** пройдено `max_iterations` URL → стоп.
- **Circuit breaker:** три ошибки подряд → стоп батча.

Если лимит достигнут, выбрасывается `RuntimeError: cost cap reached` и батч
завершается. URL, которые не успели, попадут в следующий батч автоматически (благодаря
skip-if-fresh: свежие canonicals будут пропущены, «хвост» без записей — заново).

### 10.2 Настройка лимитов

```powershell
# Увеличить лимит для большого батча
python -m src.run --source developer_mozilla_org --max-credits 200

# Маленький тест-прогон на 10 кредитов
python -m src.run --source anthropic_news --max-credits 10
```

Каждый вызов Firecrawl стоит 5 кредитов, то есть `--max-credits 100` = максимум 20
страниц за один прогон.

## 11. База данных: что где хранится

База данных — файл `data/scraped.db`, формат SQLite. Состоит из четырёх таблиц.

### `raw_content` — аудит-лог всех попыток

Сюда пишется каждый ответ от Firecrawl, независимо от того, прошёл он валидацию или нет.
**Никогда не обновляется и не удаляется** — это append-only аудит.

Ключевые поля: `source`, `source_id`, `url`, `content_hash`, `raw_payload` (JSON),
`scraped_at`, `trace_id`.

### `canonical_records` — валидированные данные

Последняя успешно провалидированная версия каждой страницы. Хранится по ключу
`(source, source_id)`. При повторном скрапинге запись обновляется, а в `change_history`
фиксируются изменения полей.

Ключевые поля: `source`, `source_id`, `url`, `payload` (JSON), `valid_from`, `raw_id`.

### `change_history` — история изменений

При каждом обновлении `canonical_records` фиксируется: что изменилось, старое и новое
значение, когда. Append-only.

### `validation_failed` — очередь ошибок

Записи, не прошедшие валидацию схемы. Имеют жизненный цикл: создаётся автоматически,
закрывается вручную через `scripts/resolve_vf.py`.

Ключевые поля: `id`, `source`, `url`, `raw_id`, `error`, `detected_at`, `resolved_at`,
`resolution`.

### Прямые SQL-запросы (только чтение)

```powershell
# Открыть базу в режиме чтения
sqlite3 data/scraped.db -readonly

# Примеры запросов:
SELECT COUNT(*) FROM canonical_records;
SELECT source, COUNT(*) FROM canonical_records GROUP BY source;
SELECT source_id, url FROM canonical_records WHERE source = 'anthropic_news';
SELECT id, url, error FROM validation_failed WHERE resolution IS NULL;
```

## 12. Трейсы: файлы аудита

Каждый батч создаёт (или дополняет) файл `data/traces/YYYYMMDD.jsonl`. Каждая строка —
это JSON-объект `span`, описывающий одно событие: начало батча, один scrape-вызов и т.д.

Трейсы предназначены для диагностики: по ним можно восстановить, что именно произошло
во время батча, какие URL обрабатывались, сколько времени занял каждый запрос.

**Файлы трейсов не удалять** — это часть аудита.

## 14. Типичные проблемы и их решение

### `RuntimeError: cost cap reached`

Батч упёрся в лимит кредитов. Это нормально: оставшиеся URL будут обработаны в
следующем батче автоматически (skip-if-fresh пропустит уже скрапленные).

Если нужно за один раз обработать больше URL:

```powershell
python -m src.run --source developer_mozilla_org --max-credits 300
```

### `source 'xxx' not found in sources.yaml`

Вы указали имя источника, которого нет в `config/sources.yaml`. Проверьте правильность
написания: имя должно совпадать с именем файла адаптера без расширения `.py`.

Доступные имена: `developer_mozilla_org`, `docs_python_org`, `anthropic_news`.

### `unresolved vf: N` — ненулевое число

В базе есть ошибки валидации. Они не блокируют батч, но требуют разбора. Используйте
`/investigate-failed <источник>` в Claude Code или просмотрите вручную:

```powershell
python scripts/resolve_vf.py --vf-id N --dry-run
```

### `empty extraction for <url>`

Firecrawl вернул пустой ответ. Возможные причины: страница не существует, сайт заблокировал
запрос (anti-bot), таймаут загрузки. Запись попадёт в `errors` (не в `validation_failed`)
и будет автоматически ретраиться в следующем батче.

### Батч не видит `.env` файл

Убедитесь, что запускаете команды из корневой папки проекта (`ParserCF/`), а не из
подпапки. Путь к базе данных и `.env` — относительные от CWD.

### Phantom-diff в `git status` на Windows

Если `git status` показывает десятки изменённых файлов без реального содержательного
изменения — это проблема переносов строк (CRLF/LF). Решение:

```powershell
git config --global core.autocrlf true
git checkout -- .
```

## 15. Глоссарий

**Адаптер** — Python-класс, специфичный для одного сайта. Содержит список URL для
скрапинга (`list_urls`) и логику извлечения ID из URL (`parse_id`). Хранится в
`src/sources/`.

**Батч** — один прогон парсера по всем URL заданного источника. Запускается командой
`python -m src.run --source <имя>`.

**canonical_records** — таблица SQLite с последней успешно провалидированной версией
каждой страницы. Это «готовые» данные.

**Circuit breaker** — предохранитель: если три вызова Firecrawl подряд завершились
ошибкой, батч останавливается автоматически.

**CostGate** — обёртка над вызовами Firecrawl, которая считает потраченные кредиты и
останавливает батч при достижении лимита.

**Firecrawl** — внешний сервис, который загружает веб-страницы и извлекает из них
структурированные данные через языковую модель. Платный, расход в «кредитах».

**page_type** — тип страницы: `article` (статья/новость), `docs` (документация),
`product` (товар), `reference` (справочная запись). Определяет, какая схема используется
для валидации.

**raw_content** — append-only таблица SQLite с полным ответом от Firecrawl для каждой
попытки скрапинга. Аудит-лог: никогда не изменяется и не удаляется.

**sanitize** — слой очистки контента от потенциально опасного содержимого (скрытые
символы, prompt injection, ролевые префиксы).

**skip-if-fresh** — механизм инкрементального обновления: URL пропускается, если в
`canonical_records` уже есть запись, обновлённая в последние N дней (`--max-age-days`).

**source_id** — канонический идентификатор страницы внутри источника. Например, для MDN
это путь вида `Web/CSS/flex-wrap`. Извлекается методом `parse_id` адаптера.

**validation_failed** — таблица SQLite с записями, которые не прошли проверку по схеме.
Требуют ручного разбора через `scripts/resolve_vf.py`.

**validation_failed resolution** — итог разбора ошибки: `fixed` (исправлено), `discarded`
(отброшено), `source_changed` (источник изменился).
