Idempotency

In computer science and mathematics, an operation is idempotent if applying it multiple times produces the same result as applying it once. The term is widely used in HTTP, distributed systems, and database design.

An HTTP method is idempotent if identical requests can be made multiple times with the same effect on the server. According to RFC 9110, GET, PUT, DELETE, HEAD, and OPTIONS are idempotent; POST is not.

Idempotency is critical for safe retry logic. When a network request fails mid-flight, it is only safe to retry automatically if the operation is idempotent; otherwise you risk duplicate side-effects.

Examples

  • Idempotent: DELETE /resources/42 — whether the resource exists or not, the end state is the same (no resource with id 42).
  • Non-idempotent: POST /orders — each call creates a new order.
  • Database: UPDATE accounts SET balance = 100 WHERE id = 1 is idempotent; UPDATE accounts SET balance = balance + 10 WHERE id = 1 is not.
